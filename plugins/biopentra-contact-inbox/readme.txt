Support desk for WordPress: Fluent Forms tickets, a ticket/message model, optional Proton Mail Bridge IMAP import (via **PHP IMAP** or an **external Python worker**), and SMTP-backed replies via wp_mail().

== User-facing name and compatibility ==

The plugin is presented in the admin as **Biopentra Support Desk**. It was previously distributed as **Biopentra Contact Inbox**. The plugin directory and text domain remain `biopentra-contact-inbox` for backward compatibility. Existing options, tables, and the `manage_biopentra_inbox` capability are unchanged.

== Features ==

* **Fluent Forms** — Select a contact form in Settings; submissions can be migrated into tickets or opened via legacy submission links (tickets are created on demand).
* **Proton Bridge IMAP import** — Choose **Worker** (recommended): Compose runs the **published** **`ghcr.io/magpern/proton-mail-worker`** image; it polls Bridge IMAP and posts to the plugin REST API (`biopentra-support/v1`), so WordPress does not need **ext-imap**. Or use **PHP IMAP (legacy)** when the PHP IMAP extension is available.
* **Proton Bridge SMTP** — Outbound support desk mail can use Bridge SMTP (STARTTLS), with scope limited to plugin mail or applied to all `wp_mail()`.
* **Tickets and messages** — Conversations are stored in custom tables: one ticket row per thread and message rows for inbound/outbound content and threading metadata.
* **Statuses** — Tickets use `open`, `pending`, and `closed`.
* **Read / unread** — Tickets track an unread flag; opening a ticket marks it read.
* **Settings tabs** — **General**, **Email / Proton Bridge**, **Sync / Worker** (import driver, mail worker token, **Check for new messages now** and **Check worker health** when using Docker, optional legacy PHP IMAP sync).

== Requirements ==

* **PHP IMAP extension** — Required only when the import driver is **PHP IMAP (legacy)**. With the **Worker** driver, inbound mail is handled by the **published** mail worker container configured in `docker-compose.yml`; WordPress does not need **ext-imap** for import.
* **Proton Bridge password** — IMAP and SMTP use the **mailbox password generated by Proton Bridge** (from the Bridge `info` output), not your main Proton account password.

== Cron ==

When the import driver is **PHP IMAP (legacy)**, scheduled mail sync uses WordPress’s cron API (`biopentra_inbox_imap_sync`). On low-traffic sites, WP-Cron may run late; for production, call `wp-cron.php` from the system scheduler (see plugin **Sync / Worker** settings for an example `curl` line). With the **Worker** driver, the worker container polls IMAP on its own schedule; WordPress cron is not used for that polling.

== MVP limitations ==

* **No attachments** in phase 1 (body-focused import and replies).
* **No IMAP IDLE** — polling/search-based import only.
* **Single mailbox / account** — one IMAP + SMTP configuration in settings.
* **Bridge passwords in WordPress** — for MVP, IMAP/SMTP secrets are stored in the options table (or may be overridden via constants where documented in code); treat the database backup as sensitive.
* **TLS / certificates** — the Bridge integration may disable strict TLS peer verification for local Bridge or self-signed certificates; use an internal network and do not expose Bridge ports to the public internet.

== Installation ==

1. Install and activate Fluent Forms if you want form-based tickets and migration.
2. Activate this plugin.
3. Open **Support Desk → Settings** (menu title may follow your “Support desk title” option).
4. On **General**, choose the Fluent Forms form when applicable.
5. On **Email / Proton Bridge**, configure IMAP/SMTP if you use Bridge; on **Sync / Worker**, choose the import driver, configure the worker token if using **Worker**, and enable legacy PHP IMAP sync only if you use that driver.
6. Ensure the **PHP IMAP** extension is enabled on the server only when the import driver is **PHP IMAP (legacy)**.

== Docker (this repository) ==

The `woocommerce/docker-compose.yml` stack adds a **`proton-bridge`** service on **`bridge-net`** (with **named volumes** for Bridge config, GnuPG, and password-store), a **`biopentra-mail-worker`** service that **pulls** the published image **`ghcr.io/magpern/proton-mail-worker:latest`** (no worker source in this repository), and attaches **WordPress** to **default** + **`bridge-net`** so the hostname `proton-bridge` resolves from PHP and from the worker. The worker listens internally on port **8080** for **`GET /health`** and **`POST /poll`** (no `Authorization`; **internal Docker network only** — **do not** publish this port). **Bearer `API_TOKEN`** is used only for worker → WordPress **`/messages/import`** and **`/worker/status`**. **`WORKER_HTTP_PORT`** is set in Compose on the worker. The stock **`wordpress:php8.3-apache`** image does **not** include **ext-imap**; use the worker path or see `docs/proton-bridge-docker.md` for networking, Bridge login, and notes on adding PHP IMAP yourself.

== Data ==

* **Legacy replies** — Optional history in `{prefix}biopentra_inbox_replies` (Fluent submission replies when that mode is used).
* **Tickets / messages** — `{prefix}biopentra_inbox_tickets` and `{prefix}biopentra_inbox_messages`.
* Fluent Forms submission tables are **not** modified by this plugin.

== Uninstall ==

If **Delete plugin data on uninstall** is enabled under **General**, deleting the plugin from the Plugins screen removes the plugin’s tables, options (including import driver and worker token hash), scheduled `biopentra_inbox_imap_sync` events, and the IMAP sync lock transient. Fluent Forms data is never removed by this plugin.
